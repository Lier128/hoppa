## 1. 目标与假设

验证四条产品假设（PRD §2.4）：

- H1：结构化活动详情能减少申请前需要额外询问的信息量。
- H2：按类型 / 时间 / 预算 / 出行方式筛选，比泛化兴趣标签更能帮用户找到合适活动。
- H3：申请—确认—群聊—评价闭环有助于提高活动完成率。
- H4：清晰展示费用、人数、集合点与安全规则，能提升参与信心。

## 2. 对象与样本

- 3–5 位目标用户（18 岁以上、在武汉学习/工作、有周末出门意愿）。
- 每人 20–30 分钟，远程或线下均可，主持人只读任务不引导。
- 样本量小，只做探索性结论，**不做统计显著性宣称**。

## 3. 任务脚本

| # | 任务 | 记录点 |
|---|---|---|
| 1 | 找到一场预算 100 元以内、周末可参加的活动，并说出时间/地点/费用 | 完成与否、耗时、复述准确度 |
| 2 | 判断这场活动是否适合自己，并提交加入申请 | 是否理解审核流程、卡点 |
| 3 | 创建一场 City Walk 活动，设置人数上限与费用方式并发布 | 表单错误次数、是否理解必填项 |
| 4 | 以组织者身份通过一条申请，并说明人数上限规则 | 是否发现容量限制 |
| 5 | 在「我的活动」里完成模拟签到，结束后提交评价并打开旅行名片 | 状态流转理解度、是否找到入口 |

## 4. 观察与记录

- 任务完成率、完成时长、误操作 / 回退次数。
- 是否能准确复述：时间、集合地点、预算、费用方式（H1/H4 的直接证据）。
- 在哪一步犹豫、是否担心安全、是否误解「演示功能」。
- 最有价值的功能 / 最想删掉的功能。
- 原话摘录（匿名），不要事后润色成结论。
