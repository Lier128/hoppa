# HOPPA 交互与页面规格

> 版本：V1.0｜用途：Vibe Coding 页面实现与验收 页面原型参考：随附 HOPPA UI 截图；首版交付响应式 Web 应用，不要求原生小程序。

## 1. 全局导航

### 桌面端

- 左侧：品牌标识、首页、同城、找搭子、发布活动、消息、我的。
- 主内容区：活动卡片、详情、表单或列表。
- 右侧可选：本周精选路线、活动小贴士或当前用户活动摘要。
- 最大内容宽度建议 1200px，主要阅读区域保持适当行宽。

### 移动端

- 顶部：页面标题、搜索或消息入口。
- 主内容区：单列卡片。
- 底部导航：首页、同城、找搭子、发布、我的。
- 活动详情中的“申请加入”使用底部固定操作栏，但不能遮挡详情内容。

## 2. 页面规格

### 2.1 登录 / 演示入口

**目的：** 让面试官快速进入体验，不因真实注册流程阻断演示。 - 展示 HOPPA Logo、口号“线上相遇，线下来聚”。 - 提供“进入体验”按钮，默认使用演示账号。 - 可选提供“切换演示身份”：普通参与者 / 活动发起者。 - 明确提示“当前为作品集演示环境，数据为模拟数据”。 - 不采集真实手机号、身份证或密码。 - 状态：初次进入、已进入演示、重置演示数据。

### 2.2 首页 / 发现

**页面目标：** 让用户在首屏理解产品，并找到一项值得查看的活动。 - 顶部：HOPPA 品牌、武汉城市切换（首版只模拟武汉）、搜索入口、消息入口。 - 主视觉文案示例：“周末别只刷手机，找个搭子一起出门”。 - 分类：City Walk、美食、展览、桌游、运动、演出。 - 活动卡片：封面、活动名、时间、地点、预算、费用方式、已报名 / 总人数、发起者头像 / 昵称。 - 精选路线：黄鹤楼漫游、东湖 City Walk 等静态样例。 - 主要操作：查看详情、进入找搭子、发起活动。 - 空状态：显示“暂时没有符合条件的活动”，并提供“清除筛选”。

### 2.3 同城

**页面目标：** 从城市内容中获得活动灵感。 - 展示同城活动回顾 / 地点推荐卡片。 - 内容包含标题、地点、活动类型、图片、作者、点赞 / 收藏状态。 - 点击内容进入内容详情；关联活动时显示“查看相关活动”。 - P0 可简化为活动内容列表；点赞、收藏、评论作为 P1。 - 示例图片使用项目素材或占位图，不使用未经授权的个人信息。

### 2.4 找搭子 / 匹配

**页面目标：** 将模糊的社交需求变成可筛选的活动需求。 - 顶部切换：社群活动 / 个人活动。 - 筛选项：活动类型、日期 / 时间、预算、出行方式、费用方式、剩余名额。 - 推荐卡片显示“推荐原因”，如“与你选择的 City Walk 类型、周末时间和预算相符”。 - 点击卡片进入活动详情。 - “开始匹配”打开偏好选择面板；提交后更新推荐列表，不应只显示静态成功弹窗。 - 匹配失败时建议扩大预算、换日期或清除类型筛选。 - MBTI 为可选标签，不是唯一匹配依据。

### 2.5 活动详情

**页面目标：** 帮助用户在申请前做决定。 - 顶部：封面图、活动标题、活动状态和类型标签。 - 关键信息：日期时间、集合地点、预计时长、预算、费用方式、人数上限、已报名人数。 - 组织者：头像、昵称、简介 / 标签、组织活动数量（演示数据）。 - 活动介绍：活动目的、流程、注意事项、是否适合新手。 - 路线：集合点与路线节点；若无地图服务，使用静态路线卡和节点列表。 - 参与者预览：头像、昵称、兴趣标签（仅演示信息）。 - 底部操作：申请加入 / 查看申请状态 / 管理活动（仅组织者）/ 安全中心。 - 异常状态：满员、已取消、已结束、本人发起的活动。 - 申请前确认时间、地点和费用规则；提交成功后显示申请状态。

### 2.6 创建活动

**页面目标：** 降低发起门槛，同时保证信息足够清晰。 - 活动标题（必填，2–40 字）。 - 活动类型（必填）。 - 日期与开始时间（必填，必须为未来）。 - 集合地点（必填，文字地址）。 - 预计时长（选填）。 - 人数上限（必填，2–30，演示版上限）。 - 费用方式（必填：AA / 各自承担 / 免费 / 待协商）。 - 人均预算区间（选填）。 - 出行方式（步行 / 公共交通 / 骑行 / 自驾 / 其他）。 - 活动介绍与注意事项（必填，10–500 字）。 - 兴趣标签（选填，最多 5 个）。 - 路线节点（选填，可添加多个）。 - 发布前预览活动卡片；成功后进入活动详情，并提示“你是本活动组织者”。 - 错误反馈需定位到具体字段，不只显示“提交失败”。

### 2.7 我的活动

**页面目标：** 让用户明确自己当前要做什么。 - Tab：准备中、进行中、待评价、已结束、我发起的。 - 每张活动卡展示标题、时间、地点、角色、状态和下一步操作。 - 准备中：查看详情、查看申请状态、进入群聊、退出活动。 - 进行中：查看路线、模拟签到、进入安全中心。 - 待评价：提交评价、查看活动回顾。 - 已结束：查看详情、查看评价、查看旅行名片。 - 我发起的：管理申请、编辑非关键字段、取消活动。 - 空状态提供“去找搭子”或“发起一个活动”入口。

### 2.8 活动管理（组织者视角）

- 申请列表：申请者头像、昵称、标签、申请留言、申请时间、状态。
- 操作：通过、拒绝；通过前检查人数上限。
- 成员列表：组织者标识、参与者状态、模拟签到状态。
- 活动状态操作：开始活动、结束活动、取消活动。
- 修改集合地点或时间时，二次确认并提示“需要通知成员”。
- 首版不实现真实通知，只在页面内展示操作结果。

### 2.9 消息 / 活动群聊

- 消息列表按最近活动排序，展示活动名称、最后一条消息和时间。
- 群聊顶部显示活动标题、日期和“活动详情”入口。
- 消息气泡区分当前用户与其他演示成员。
- 输入框支持发送文本消息；桌面端 Enter 发送，Shift+Enter 换行。
- 空群聊展示活动规则 / 集合信息提示。
- 消息本地持久化；不连接外部即时通讯服务。
- 举报 / 屏蔽入口可从消息菜单打开。

### 2.10 路线规划

- 显示路线标题、城市、预计时长、步行 / 公交等方式、路线节点顺序。
- 节点包含地点名、简短说明、建议停留时间。
- 可以标记“已到达”或“加入我的活动”，但只模拟操作。
- 不显示伪造的实时路况、真实定位点或导航精度。
- 无地图 API 时使用静态地图插画 / 路线示意图 + 结构化节点列表。

### 2.11 安全中心

- 入口：活动详情、我的进行中活动、群聊菜单。
- 展示：活动信息摘要、集合地点、组织者、参与规则、线下安全建议。
- 操作：复制活动信息、举报问题、退出活动、演示紧急求助。
- 演示紧急求助必须先弹确认框，说明不会拨打电话、获取定位或向外部发送数据。
- 举报表单：举报对象、原因、补充说明；提交后显示“已记录（演示）”。
- 不承诺“全程监管”“绝对安全”或“实时保护”。

### 2.12 个人中心

- 个人头部：头像、昵称、城市、简介、兴趣标签。
- 统计卡：参加活动数、发起活动数、获得评价数（演示数据）。
- 快捷入口：我的活动、旅行名片、收藏、设置、安全中心。
- 编辑资料：昵称、头像选择、简介、兴趣标签、出行偏好、预算偏好。
- 资料变更需同步到活动组织者 / 参与者展示位置。
- 不显示或收集身份证、真实住址、手机号等敏感信息。

### 2.13 评价与旅行名片

- 活动完成后，用户可给活动体验打 1–5 分并选择标签：组织清晰、路线有趣、氛围轻松、时间安排合理等。
- 评论选填，建议 0–200 字。
- 提交后不可重复提交；若允许编辑，必须提供明确编辑入口。
- 旅行名片展示活动名、时间、地点、路线节点、个人感受和 HOPPA 品牌。
- 分享操作默认复制文案或生成本地图片，不自动发布到第三方平台。

## 3. 交互状态规范

所有关键操作至少覆盖：默认态、Hover / Focus（桌面端）、加载态（如有异步模拟）、成功态、失败态、空状态、禁用态、危险操作二次确认。

统一文案原则： - 具体说明发生了什么以及下一步可以做什么。 - 不用“系统错误”作为唯一错误文案。 - 不用虚假的“匹配成功”替代真实筛选结果更新。 - 对演示功能明确标注“演示”，不让用户误以为已调用真实服务。

## 4. 视觉规范

- 品牌气质：年轻、轻松、友好、有一点潮流感，但避免幼稚或过度装饰。
- 主色：粉 / 紫渐变；背景为暖白和浅桃色。
- 卡片：圆角、留白、明确的标题和元信息。
- 标签：活动类型、费用方式、活动状态使用统一颜色和样式。
- 主按钮：每屏仅突出一个主要动作；危险操作独立呈现。
- 图标：统一使用一套图标库，避免 Emoji 与线性图标混用过多。
- 图片：优先活动场景图，保持比例一致；无图时使用有品牌感的占位图。
- 可访问性：按钮可键盘聚焦；正文与背景有足够对比；表单错误信息可见。

## 5. 关键演示脚本

### 脚本 A：参与者完整流程（2–3 分钟）

1.  首页选择 City Walk 分类。
2.  筛选预算和周末时间。
3.  打开“黄鹤楼漫游”或其他样例活动详情。
4.  查看时间、集合点、费用方式和人数。
5.  提交加入申请。
6.  切换到组织者演示身份或打开管理视图，通过申请。
7.  进入活动群聊并发送一条消息。
8.  进入“我的活动”，完成模拟签到。
9.  将活动状态推进到待评价，提交评价。
10. 打开旅行名片并复制分享文案。

### 脚本 B：发起者完整流程（2–3 分钟）

1.  点击发布活动。
2.  创建“周末东湖 City Walk”，填写时间、集合点、人数和费用规则。
3.  发布后进入活动详情。
4.  查看并处理申请。
5.  开始活动、查看成员签到状态。
6.  结束活动并查看评价入口。

### 脚本 C：安全边界演示（30 秒）

1.  从进行中活动进入安全中心。
2.  查看集合信息和安全建议。
3.  打开“演示紧急求助”，展示确认文案。
4.  说明原型不请求定位、不拨打真实电话、不向外部发送数据。

## 6. 页面验收清单

- [ ] 所有主导航可点击且目标页面正确。
- [ ] 所有活动卡片可进入详情。
- [ ] 搜索 / 筛选会改变真实列表状态。
- [ ] 创建活动表单字段校验完整。
- [ ] 加入申请和组织者审核状态互相同步。
- [ ] 满员 / 已取消 / 已结束活动不可继续申请。
- [ ] 我的活动 Tab 与状态规则一致。
- [ ] 群聊消息发送后即时出现，刷新后保留。
- [ ] 模拟签到、结束活动、评价能按状态流转。
- [ ] 个人资料编辑后全局同步。
- [ ] 安全功能明确标注演示边界。
- [ ] 移动端无横向溢出；桌面端布局舒适。
- [ ] 重要操作有成功、失败、空状态和二次确认。
- [ ] 重置演示数据后可重新执行演示脚本。
